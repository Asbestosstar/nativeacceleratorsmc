# Native Accelerator Renderer v2 — Metal/OCLP + backend-selective lifecycle

This pass changes renderer integration rather than adding another small Metal menu patch.

## Renderer selection

Native Accelerator owns an independent renderer preference with four choices:

- Automatic
- OpenGL
- Vulkan
- Metal

Minecraft 26.3's `PreferredGraphicsApi` enum remains untouched. The Native Accelerator option replaces
Minecraft's Graphics API option at the first `OptionsList.addSmall(...)` call in
`VideoSettingsScreen.addOptions()`, which is the Display group. The call-site injection is `require=1` so
a mapping/version mismatch is visible instead of silently falling back to the vanilla three-value menu.

`-Dnativeaccelerator.graphicsApi=metal` remains a direct startup override for testing.

## Backend isolation

Renderer services now start only for the backend Minecraft actually created:

- Metal: no Vulkan companion/probe/initialization.
- OpenGL: no Vulkan companion/probe/initialization.
- Vulkan: Native Accelerator's Vulkan companion may start after the Vulkan device succeeds.
- server/server-only renderer role: Vulkan companion stays off.
- dedicated server: no client renderer path.

## OCLP / older Intel Mac Metal

Metal device probing/creation uses SDL GPU properties when available and enables
`SDL_PROP_GPU_DEVICE_CREATE_METAL_ALLOW_MACFAMILY1_BOOLEAN` by default. Disable this experiment with:

```
-Dnativeaccelerator.renderer.metal.allowMacFamily1=false
```

The backend does not request SDL sRGB render targets, which is required for the MacFamily1 opt-in.

## Performance work in this pass

This is a first full-backend throughput pass, not just a Metal selector:

1. Metal mapped buffer writes are deferred and coalesced into the frame command buffer.
2. All dirty buffer ranges in a flush are packed into one SDL transfer buffer and one copy pass.
3. Uniform-only RenderPearl buffers stay in a CPU shadow and are pushed directly as SDL GPU uniforms,
   avoiding redundant GPU buffer uploads.
4. GPU buffer-to-buffer and texture-to-texture copies stay on the GPU.
5. Transient multi-upload memory is packed into a single larger GPU buffer rather than one allocation per
   input.
6. Render-pass uniforms/samplers/storage buffers are rebound only when dirty or after a pipeline switch,
   rather than before every draw.
7. Draw calls, pipeline binding, uniform pushes, storage-buffer binding, sampler binding, vertex/index
   binding, scissor changes, command acquisition/submission, and GPU lifecycle hot paths use typed LWJGL
   SDL calls instead of reflective invocation where practical.
8. Metal allows up to three frames in flight by default for throughput. Override with:

```
-Dnativeaccelerator.renderer.metal.framesInFlight=1|2|3
```

9. Cloud `R8_SINT` texel-buffer input remains supported through SPIR-V -> MSL storage-buffer lowering.

## Deliberate remaining work

The full Minecraft scene renderer is not moved wholesale into native code in this patch. The intended next
performance steps are measurement-driven: persistent section arenas, GPU visibility/indirect draws,
pipeline/resource binding caches, and replacing remaining reflective SDL setup paths only where profiles
show meaningful cost. Minecraft object graphs stay Java-side; compact primitive scene snapshots are the
native boundary.

## Buildfix 5: first-class selector and strict backend isolation

The Graphics screen integration no longer depends on replacing Minecraft's three-value
`PreferredGraphicsApi` widget. `VideoSettingsMetalOptionMixin` injects at the HEAD of
`VideoSettingsScreen.addOptions()` and inserts a full-width Native Accelerator renderer selector
directly into the Display section. `OptionsSubScreen.addContents()` has already created the list before
that call, so selector visibility no longer depends on any particular vanilla option-list invocation.
The vanilla Graphics API control is removed when its exact 26.3 call shape is present, but visibility of
the Native Accelerator selector does not depend on that removal.

This is intentional: Minecraft 26.3's vanilla option cannot represent Metal because the field type is
`PreferredGraphicsApi`, whose only values are Default/OpenGL/Vulkan. Native Accelerator persists its
four-value choice independently and mirrors only a safe vanilla value into options.txt.

Backend initialization is now strict:

* explicit Metal: Metal -> OpenGL fallback; no Vulkan backend candidate;
* explicit OpenGL: OpenGL only; no Metal or Vulkan candidate;
* explicit Vulkan: Vulkan -> OpenGL fallback;
* automatic: capability-driven candidates; Vulkan-specific Native Accelerator services start only if
  Vulkan is the backend that actually creates a device;
* Minecraft's separate `VulkanBackend.checkBackendAvailable()` call is suppressed when Metal or OpenGL
  is the explicit Native Accelerator choice;
* server-only renderer role never initializes the Native Accelerator Vulkan companion.

For OCLP/older Metal-capable Macs, SDL's MacFamily1 opt-in is enabled by default. An explicit Metal
selection is allowed to attempt `SDL_CreateGPUDeviceWithProperties` even if SDL's non-creating support
probe is conservative. Startup diagnostics now print the probe result and the actual selected backend.

The Metal backend is also a throughput rewrite rather than a thin API shim: dirty-state-only resource
binding, direct LWJGL SDL GPU calls on the draw hot path, batched dirty-buffer uploads in one transfer
buffer/copy pass, GPU-to-GPU copies, three frames in flight by default, and SPIR-V -> MSL resource
lowering including Minecraft's R8_SINT cloud texel buffer.

## Buildfix 6: OCLP selector hardening

The selector insertion moved to `VideoSettingsScreen.addOptions()` HEAD. This is intentionally less
fragile than anchoring to the first `OptionsList.addSmall(...)` invocation and remains valid if another
mod or patched client reshapes the vanilla Display group.

`-Dnativeaccelerator.graphicsApi=<metal|opengl|vulkan|default>` is now a true force override and wins
over stale non-default vanilla state. Explicit Metal/OpenGL also suppress Minecraft's standalone eager
Vulkan availability probe. A persisted Native Accelerator `Automatic` choice suppresses that eager
probe as well; Vulkan is touched only if backend fallback actually reaches Vulkan.
